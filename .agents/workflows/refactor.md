# Refactoring Workflow

Goal:

Improve code quality without changing behavior.

Rules:

- Preserve runtime behavior.
- Preserve public APIs.
- Preserve UX.
- Preserve architecture.
- No feature additions.
- No behavior changes.

Before coding:

Explain:

- Why refactoring is needed
- Scope
- Risk

Wait for approval.

After implementation:

Report:

- Files modified
- Logic moved
- APIs preserved
- Runtime equivalence
- Validation
