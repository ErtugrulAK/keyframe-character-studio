## [1.1.0-rc.3] - 2026-10-27

The third release candidate of 1.1.0: the `feature/motion/kcs-master-implementation`
work (the master-review work packages and manual QA rounds C1–C12) on top of the
V7.2 integration (`15f3be1`). The package metadata now reads `1.1.0-rc.3`.

### Added
- Masks you draw and edit on the canvas: Rectangle, Ellipse and Pen masks on any layer, point and handle editing, keyboard nudging, and per-mask animation of the path and its properties.
- A layer tree with parenting, locks and a deletion review; Track Matte relationships with source navigation ("Select Source" / "Back to …"); mask-constrained colour correction for images (scene v3).
- Basic shapes convert to editable paths; the Pen places a corner on click and a smooth point on drag; C, a double-click and Alt-drag switch point types and link or break handles.
- The X/Y coordinate overlay and readout, with axis badges at the visible end of each axis.
- Alt-drag of the first or last selected keyframe stretches the selection in time; easing code can be pasted into the Motion Curve Editor.
- OGraf export capability report per layer before exporting.

### Changed
- The Inspector is split into Properties, Masks and Layer tabs; the timeline property tree follows motion-tool order with per-mask groups; the property stopwatch is replaced by the row's "+".
- Docks, the timeline and the stage: one clean slide per panel toggle, a fixed-size drawing surface (no redraw or shimmer when panels move), and reduced motion honoured everywhere.
- Phones, tablets and resized or half-screen windows: the docks close (and open over the stage on a phone) when the stage has no room, and the header, toolbar and timeline rearrange instead of clipping.
- A shape's border keeps its authored width whatever the layer's scale and zooms with the view (OGraf output alike); the editor chrome (artboard border, selection frame) stays thin at every zoom.
- The Motion Curve Editor is redesigned: no captions on the graph, the handle numbers in one row, icon presets, a compact preview and code row; it fits a phone.
- A new Track Matte hides its source, as in After Effects; the LAYER MASKS card is simplified to "Cut a hole" and an on/off eye.

### Fixed
- A second mask's "Cut a hole" cut nothing (the stack was an alpha mask), and editing the first of two masks did not repaint the layer until editing was re-entered.
- Number fields keep the typed text, so values such as 0.1 can be typed.
- Autosave saves within 10 s of the first change and reports its real state.
- Animation transfer pastes motion relative to the target's own pose.

### Removed
- The canvas pick-whip for Track Matte sources, the IN/OUT preset and DUPLICATE cards in the Layer tab, and the "Restored from this browser's autosave" chip.
- C10's frame-rate retiming was reverted: changing the FPS keeps every key on its frame.

## 1.1.0 candidates rc.1–rc.2 and the work integrated up to V7.2

Everything below was recorded under `[Unreleased]` before the rc.3 cut. It covers
the rc.1 and rc.2 candidates and the work integrated on `main` after them, up to
`39f6414`.

### Added
- A layer **OPACITY** field in the Transform section, shown as a percentage next to an **Add/Remove Keyframe** button. The field writes through the same `opacity` channel the timeline already animates: while the channel has no keyframe it sets the layer's static opacity, and once it has one, the edit lands on the current frame (adding a keyframe there when the frame is empty) — so an entrance fade is authored by setting 0% on one frame and 100% on another, and each keyframe keeps its own value. It works for every layer kind: shapes, text, images, freeform and cloners.
- Stroke controls for text: a text layer now owns the same fill/stroke paint as shapes, so the Appearance card and the Text card both expose its stroke colour, alpha, width and enable switch, and the canvas paints the authored outline instead of a fixed one. The outline defaults to the canonical 0.5 width text always had, the alignment control stays hidden for text (its renderer cannot split a centered stroke), and the OGraf export writes the authored stroke width, opacity and enabled state for text instead of a hardcoded 0.5.
- Layers can be bonded to each other: select two (or more) layers and press **Bind** in the Inspector, and a position change on either one — a stage drag, the Inspector's position fields, or a multiple selection — moves the others by the same world-space delta. Rotation, scale and opacity stay independent, so a bond is not a parent-child transform; **Unbind** releases it. A copy, a mirrored duplicate and a Boolean group never inherit a bond, and an ancestor/descendant pair is refused with an explanation instead of being moved twice. The bond is saved with the document.
- Boolean operations now accept more than the closed vector shapes: a freeform layer contributes its canonical path, and a text layer contributes its own traced outline — the letters themselves, counters included — so a text and a shape can be unioned, subtracted, intersected or excluded. A text the renderer draws differently (a staggered text animates per character) or an empty text is not offered as an operand, and an environment without a canvas reports the empty result instead of substituting a bounding box. The Inspector's Boolean hint and its section description name the operand kinds they now accept.
- OGraf packages are importable: selecting the `.zip`/`.ograf` the exporter wrote opens a report and, on confirm, replaces the project with the scene the package carries. The archive is decoded in memory with entry-count, entry-size and package-path guards, prototype keys and unsafe, duplicate or reserved paths are refused, and a package without a scene is refused rather than half-imported.
- One import control in the header instead of several: the selected file is classified by what it **contains**, so a KCS project, a legacy project, an OGraf manifest and a Lottie animation all import through the same button, each with its existing behaviour (and the Lottie animation still showing its report before anything is replaced).
- A Lottie (bodymovin) import path: selecting a Lottie file parses it in memory and opens a report that lists the blockers and the losses with their source paths and next steps **before** anything is applied — Cancel leaves the project untouched, and only "Import and replace project" applies the scene through the same validated path the project import uses. Imported layers keep the shapes, text and images they had: a path, a rectangle, a rounded rectangle, an ellipse and a solid all become a freeform whose own path draws exactly the imported geometry, while text and images keep their existing KCS types — so an imported scene neither loses its curves nor risks an export refusal caused only by the layer type the importer picked.
- A state consistency check for the repository: `node scripts/check-state-consistency.mjs` fails when the live documents contradict the tag/`main` SHA, when the roadmap and the next action disagree, or when the handoff bundle carries a stale status, a superseded upload instruction, source/test copies, collapsed Windows paths or secret markers.
- A first-export path for new users: a labelled "First export help" panel next to Export lists the three steps, offers a readiness check that reports what would block an OGraf export (reusing the existing export diagnostics), and states that nothing is written until you export. The readiness answer is a pre-flight summary; a scene changed afterwards is recompiled when the export runs.
- The timeline keyframe diamonds are keyboard operable: each one is a named button in the tab order, `Enter`/`Space` selects the keyframe and moves the playhead (and selects the part on the parent lane), and `ArrowLeft`/`ArrowRight` walk focus along the lane in frame order.
- The value graph's keyframe points are announced with their frame and value, and its decorative axes and curve stay out of the accessibility tree.
- Bezier tangent handles can be authored directly on the stage: select a single freeform layer, click a vertex to reveal its handles, drag a handle to reshape the path live, and double-click a vertex to toggle corner ↔ smooth. Each drag is a single undo step and `Escape` cancels one without recording history.
- Track-matte source relationships are now visible in the outliner for both relationship models (`Mask → <source name>`), and unnamed layers fall back to their ids in the matte source pickers.
- The Track Matte V2 card's source select carries an accessible label.
- Actionable OGraf export diagnostics: every blocking diagnostic now reports a stable title, the failing layer or feature, the reason, and a concrete next step, and it never reports success while export is blocked.
- Non-blocking OGraf warnings are surfaced as a compact grouped notification instead of being silently dropped.
- Package materialization failures now carry stable failure codes; filesystem guidance states the trusted-directory requirement, the unsupported hostile-concurrency case, and avoids claiming perfect OS-level protection. Machine paths are reduced to a display-safe form.
- The value graph's per-segment badges now state which easing the evaluator ACTUALLY applies — HOLD first, then a complete temporal handle pair, stored control points, autoBezier, stored name (`effectiveSegmentAuthority`, the evaluator's own module) — and ride on screen-reader semantics: each badge is a `role="img"` node named `Segment frame X to Y: …`, the handle-pair and control-point branches share the BEZ label distinguished by `data-segment-easing` (`bezier` vs `cubic_bezier`), and the real-browser accessibility contract asserts this exposed segment truth (a segment stored as `linear` yet driven by its control points is announced BEZ, never LIN) instead of the old blanket demand that every graph SVG text be `aria-hidden`.
- A durable history regression for the #57 segment-scope preset: `src/tests/temporalPresetHistory.test.tsx` drives the real provider seam (`applyTemporalHandlesToSegment` → `useTimeline` → `setTracks` → `useHistory`) and pins that one preset application is ONE undo entry — a single undo restores both endpoints and the evaluated behavior, a single redo restores both, and the undo ladder below the entry reaches the prior real action — that the neighbor segment is untouched, and that a HOLD or last-key refusal consumes no undo action at all. The test covers the shipped implementation; it changes no product behavior.

### Changed

- The left toolbar collapse E2E contract now waits for the docked edge to genuinely settle instead of a one-shot target-width snapshot: `useDockedPanelEdge` commits the target class before the frame ease's first animation-frame write, so the old reopen predicate could resolve true on that pre-motion flash and the driver's next measurement saw the reversed, mid-flight stage (the V71 full-suite red, stage 908 where 548 was expected). The spec-local settled-edge gate requires the inline edge-width override handed back to the stylesheet plus an unchanged geometry signature across consecutive animation frames — it distinguishes pending start, in-flight motion and completion, and survives the reduced-motion snap. ### Fixed
- P0-58 (PR #58, F5a math) — `endpointSlopesFromHandles` signed the divergent endpoint readings by the *reflected-parameter* derivative order instead of the raw coefficient sign: at the exit the Taylor series in t = 1−s alternates, so the k-th-order coefficient enters with (−1)^k. `x′(1)=x″(1)=0, y′(1)=0, y″(1)≠0` (e.g. handles (1,0.5)/(1,1)) read −Infinity where the live ratio diverges **+**Infinity. Finite equal-order L'Hôpital limits and the identity-corners (slope 1) are unchanged; only the cusp sign rule moved. `segmentVelocityScale` also refuses numeric-range failures as `overflow-result` instead of returning a fake-ok scale: a frame difference that overflows to Infinity from finite inputs (`k=0, deltaFrames=Infinity`) and a displacement that underflows k to exactly 0 (the bridge would flatten every velocity to 0 and null its inverse).
- P0-58 R5 follow-up (V7.1 numeric hygiene) — a *real but unrepresentable* endpoint slope no longer lies: when an equal-order L'Hôpital ratio — or a live first-order ratio — leaves the IEEE double range, `endpointSlopesFromHandles` returns the existing unavailable sentinel `{kind:'cusp', value:NaN}` instead of `{kind:'limit', value:±Infinity}`, a fabricated cusp-∞ over a live first-order x, or a plausible zero from total underflow (supervisor repros: (0,0)/(MIN_VALUE,MAX_VALUE) read limit +∞ — the analytic ratio ≈3.6e631 is a finite real, not a vertical tangent; (0,0)/(MAX_VALUE,MIN_VALUE) read limit 0 and (MAX_VALUE,MIN_VALUE)/(0.5,0.5) read regular 0 — the true ratio MIN/MAX ≈2.8e-632 is nonzero, so the zero was a lie). An exactly-zero numerator keeps its truthful 0, a subnormal-but-nonzero ratio (exact 2·MIN) keeps its reading, and true divergent cusps keep signed ±Infinity; finite extreme limits are untouched (exact 2^1000/2^-23 = 2^1023 still reads `limit`; one octave further, 2^1000/2^-24, is the NaN sentinel). `handlesFromEndpointSlopes` now reports the existing `lossy` flag truthfully for *structural* nonrepresentability: total collapse (±MIN_VALUE at outX 0.42 stores ±0; exitSlope 1e-20 stores inY exactly 1 — pinned both signs, including the IEEE half-ULP asymmetry at 1 where −2e-16 collapses while +2e-16 survives as pred(1)), and partial subnormal quantization whose forward read-back differs from the representable request (3·MIN at outX 0.5 stores 2·MIN and reads back 4·MIN; 3e-320 stores 2550·MIN and reads back 2.9995e-320). Exactly representable on the read-back — e.g. the power-of-two ladder 10200·MIN at outX 0.25 storing exactly 2550·MIN — keeps `lossy: false`, and ordinary normal-range rounding (1-ULP at 0.7; ~30% read-back drift on a surviving pred(1) exit) is NOT flagged: the flag marks lost information, not every IEEE rounding, and asserts no universal error bound. `clamped` keeps its exact envelope-only meaning. No new types, error enums or API surface; 13 new regression tests.
- P0-57 — the timeline stopwatch arm captures the authored-local pose again. The arm path referenced an `authored` pose value it never declared (a `TS2304` on the branch, a `ReferenceError` at runtime), so arming an off channel at a live animated pose failed instead of keying it; the restored `resolveAuthoredLocalTransform` capture keys the evaluated container-local authored pose under a transformed parent without changing the evaluated world pose.
- The Lottie import report tells the truth about half easing handles. A continuing segment with one readable Lottie handle and no usable counterpart used to pass silently, and the unreadable-incoming warning claimed "imported as linear" even when the readable outgoing half had already made the segment evaluate on KCS's default cubic; the complete-pair gate in the evaluator ignores a lone handle either way. Those segments now gain the existing `LOTTIE_UNREADABLE_EASING` warning at the missing or unreadable half's `.o`/`.i` path, naming the fallback the segment actually gets, with no duplicate for the same field and none at all for plain handle-less, HOLD, terminal, roving or expression segments. Mapped timings, handles and serialized scene output are byte-for-byte unchanged for every document; only the report changed.
- N3 PR-1 — bounded numeric acceptance at the import boundary (PR #14, merged at `84ca0ac`). A tampered file declaring `fps: 0.4` used to pass the positivity-only boundary, get rounded to **zero** by the state sanitizer, and freeze the playhead through `1000 / 0 = Infinity` with no diagnostic; `totalFrames` was accepted at `>= 1` while the state silently clamped `[10,1200]` and rounded (accepted ≠ applied); canvas edges accepted any finite positive number; the legacy route had **no numeric policy at all**; and a numeric unsupported version re-routed through the legacy shape and imported. The single boundary now refuses — never repairs — on both document kinds: finite `fps` within 0.5–240, integer `totalFrames` within 10–1200, canvas edges within 2–16384 (fractions stay legal because the Lottie mapping produces them), the legacy `projectResolution` numeric edges under the same range (a non-object keeps the documented drop-to-default), and a numeric legacy `version` outside [1,2] refuses with `KCS_IMPORT_UNSUPPORTED_VERSION`. `sanitizeProjectFps` gained a round-to-zero floor as defense-in-depth for every caller. 34 boundary/sanitizer rows plus four real-hook apply guards (a refused document fires zero state setters and never re-requests the history baseline; a tampered autosave refuses at restore with the storage bytes intact). Record: `reports/progress_181_n3_import_boundary_pr1.md`.
- SAFE-01 — the autosave engine is now an ownership-tracked compare-and-swap writer (PR #13, merged at `5ee9909`). The interval tick serialized unconditionally, external writes were never observed, the conflict check compared a stale in-memory value, and the first completed tick captured whatever the document happened to be — an edit inside the first 10 seconds froze that baseline and silently disabled autosave behind a healthy badge. A tab now writes only an earned (dirty) document, and only when the shared key still holds the exact value it last read or wrote; mismatches adopt the observed value and pause, surfaced by the amber conflict badge and a one-time toast instead of a silent overwrite. Import and reset are explicit document replacements and re-adopt the key. The read-to-write window inside one browser profile stays the documented residual race (pinned honestly, not claimed fixed). ### FPS/TIMEBASE CONTRACT (manual QA round 4, part 2 — release critical)

The ONE mapping between frames and time is `seconds = frame / fps` and
`frame = seconds * fps`; `src/utils/timebase.ts` is its named authority and every
conversion in the editor goes through it.

- The project FPS is an authored **time mapping**, never a redraw budget. Changing it re-maps frames to
  seconds; it does not change what the viewer sees.
- The monitor/browser refresh rate has **no** effect on authored duration: playback integrates elapsed
  wall-clock time and steps the playhead by whole authored frames (`usePlayback`). A dropped or throttled
  callback recovers its time instead of stretching the animation. 30, 60 and 120 FPS authorings of the same
  animation reach the same frame at the same instant, and the same midpoint at half the duration.
- The FPS is a positive **whole** number of frames per second. Fractional rates such as 59.94 are NOT
  supported and are never faked: the Lottie importer rounds `fr` and reports `LOTTIE_FRACTIONAL_FPS`, and
  the editor offers 24/30/60/120 with 60 as the new-document default. A document whose FPS cannot carry the
  mapping (0, negative, non-finite, fractional) keeps the current rate at the FPS authority.
- Sequence duration: the timeline's duration field and its `1s…10s` presets write `round(seconds * fps)`
  frames and read `frameToSeconds`, so the seconds the user types are the seconds the animation lasts.
- Save/load: `fps` and `totalFrames` are persisted and restored unchanged, so a reloaded document keeps its
  exact duration.
- OGraf: the package carries the same `fps` on SceneData and asks for it in `renderRequirements.frameRate.ideal`;
  the generated runtime advances by elapsed time (`|targetFrame - startFrame| / fps * 1000` ms → progress).
  An exported graphic therefore keeps its wall-clock duration in a host whose own timeline FPS differs — a
  **Reality Hub Timeline FPS does not have to match the KCS FPS**; only the graphic's frame count and FPS
  define its duration.
- Any GIF/video export (round 4, part 3) must map `frameDelayMs = 1000 / fps` per authored frame, for the
  same reason: frame count × delay = wall-clock duration, independent of the encoding cadence.

### DEV FRESHNESS CONTRACT (manual QA round 4, part 2)

Stale **app code** must never be the explanation for "the LAN URL shows old content".

- This repository has **no service worker and no PWA manifest**, and the dev server is reached over plain HTTP
  (`http://172.16.0.172:5173`), which is not a secure context: `navigator.serviceWorker` and Cache Storage do
  not exist there, so no offline shell can be registered on that origin. The only `localStorage` keys the app
  writes are the autosave document and the custom presets.
- A secure dev origin (localhost/HTTPS) is the one place a stale service worker could survive a rewrite of the
  dev server, so a dev-only guard (`src/utils/devFreshness.ts`, called from `main.tsx`) retires any
  registration it finds. Retired registrations no longer intercept navigation; their caches are left alone
  because a cache with no controlling worker is never served.
- When the dev server is running, a fresh navigation gets current source: Vite answers the entry document and
  every source module with `Cache-Control: no-cache` + ETag (verified against a running dev server), so
  content is revalidated rather than reused.
- The entry **document** additionally answers `Cache-Control: no-store` in dev (the `kcs-dev-document-freshness`
  plugin in `vite.config.ts`), so no intermediary between a LAN browser and the dev server may replay a stored
  document. It is deliberately narrow: modules, public assets and pre-bundled dependencies keep their own dev
  caching, and a production build keeps its immutable hashed-asset caching.
- An offline navigation cannot masquerade as a live instance: with no service worker there is no offline shell.
- What is NOT stale code: the editor restores the last autosaved **document** from `localStorage` on boot, so a
  returning LAN user sees their previous project (its scene title and its layers) rendered by current source.
  That is persistence, and it is a separate axis from code freshness.
