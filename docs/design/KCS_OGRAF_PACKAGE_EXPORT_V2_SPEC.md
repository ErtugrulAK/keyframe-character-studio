# KCS OGraf Package Export V2 Specification

## Decision

`Export as OGraf Package` produces a deterministic ZIP whose extraction root is the package root. The archive contains the exact package-relative tree generated by KCS. Direct folder export is not used because browser support is not portable and the existing project has no File System Access abstraction. The existing single-file JSON project export remains unchanged and is labeled separately; the existing OGraf ZIP path is retained as the legacy OGraf export until the V2 menu action is available.

V2 is a KCS exporter version. The generated document remains OGraf v1 and keeps the official `$schema` URL.

## Evidence-backed output tree

```text
<sanitized-graphic-name>-ograf.zip
├── <sanitized-graphic-name>.ograf.json
├── graphic.mjs
├── scene.kcs
└── assets/
    ├── images/       (only when verified image bytes exist)
    └── fonts/        (only when verified font bytes exist)
```

The corpus contains no archive examples and no universal helper/runtime tree. Therefore KCS MUST NOT add `package.json`, `index.html`, `package-view.mjs`, `package-core.mjs`, Grafstage runtimes, vendor licenses, or `v_zd` blocks merely to resemble one reference family. The manifest `main` field remains authoritative if a future caller supplies another safe main filename.

## File responsibilities

- `<name>.ograf.json`: official OGraf v1 manifest. Required fields: `$schema`, `id`, `name`, `main`, `supportsRealTime`, `supportsNonRealTime`. Optional public schema, version, description, render requirements, and action metadata are emitted only when supported by KCS.
- `graphic.mjs`: generated custom-element runtime. It uses the existing KCS OGraf evaluation/rendering behavior and implements the realtime lifecycle.
- `scene.kcs`: internal KCS scene payload for reproducibility/debugging. It is not presented as an OGraf standard field.
- `assets/images/*`: verified browser-owned image bytes only.
- `assets/fonts/*`: verified browser-owned font bytes only. KCS never downloads or bundles proprietary font binaries implicitly.

## Naming and paths

- Graphic download names are normalized with Unicode NFKD, ASCII-safe `[a-z0-9._-]` characters, collapsed hyphens, and a deterministic `graphic` fallback.
- Package-relative paths use `/`, reject empty paths, absolute paths, drive-letter paths, and any `..` segment.
- Duplicate requested asset paths receive a deterministic hash suffix derived from their source identifier.
- Archive entries use package-relative paths without a wrapper directory because that is the current KCS behavior and no reference archive disproves it.
- Manifest `id` stays deterministic and slash-free. The current content fingerprint behavior is retained for backward compatibility unless a caller supplies an explicit stable `graphicId`.

## Metadata and bindings

- Public text/image bindings use the existing `publicTextFields` and `publicImageFields` options and are represented in the manifest `schema`.
- KCS-only binding metadata MUST NOT be exposed as an unprefixed OGraf field. Vendor extensions are omitted unless a verified downstream contract is explicitly provided.
- `supportsRealTime: true` and `supportsNonRealTime: false` remain the honest KCS capability declaration.
- `scene.kcs` is the only internal payload; it is not required for an external OGraf renderer but is included in the deployable KCS package.

## Asset behavior

- Data URLs are normalized by the existing legacy compatibility preparation path into deterministic bytes.
- Local/browser-owned catalog entries may provide `binaryContent`; Node materialization may use `sourcePath`.
- External URLs are not fetched unexpectedly. Portable export rejects unverified external/missing assets with diagnostics.
- Fonts follow the same provenance rule as images. A text scene without verified font bytes is blocked with a remediation diagnostic instead of silently substituting a font.
- Video remains unsupported by the current OGraf validation contract; no fake video file is emitted.

## Browser strategy

`fflate` is already an approved project dependency and is used by `createOGrafBrowserZip`. The browser flow is:

```text
exportProject()
→ prepareLegacyOGrafExport()
→ compileOGrafPackage()
→ validate diagnostics
→ createOGrafBrowserZip()
→ Blob(application/zip)
→ browser download
```

`OGraf Package` uses the V2 ZIP path above. `OGraf Single File (Legacy)` uses the same canonical preparation/compiler only to obtain the generated runtime module, then downloads `graphic.mjs` as a standalone JavaScript module. It does not claim to package local resources; resource-requiring scenes remain subject to the canonical validation policy.

V2 adds the explicit `OGraf Package` menu action while keeping the standalone `OGraf Single File (Legacy)` artifact available. No new dependency is required. Direct folder export may be added later only behind a separate browser capability adapter.

## Backward compatibility

- Existing project JSON export is unchanged.
- Existing OGraf compiler/evaluator/rendering authorities remain canonical.
- Existing serialized scene fields, masks, Track Matte, animation, images, and fonts retain their current validation and output behavior.
- Unsupported features remain explicit export diagnostics; V2 MUST NOT silently drop them.
- Legacy single-file export remains available in the Export menu.

## Error and security contract

- Block export when any ERROR diagnostic remains.
- Deduplicate user-facing root-cause diagnostics.
- Never interpolate unsanitized user values into package paths, archive entries, SVG IDs, or runtime markup.
- Do not write outside a selected Node output root during filesystem materialization.
- Browser ZIP entries must be deterministic for identical plans.

## Test strategy

Focused tests MUST cover the exact output tree, manifest/main references, deterministic ZIP bytes, relative asset paths, collision suffixes, traversal/absolute-path rejection, repeated export stability, image/font inclusion, and representative shape/text/animation/mask/Track Matte scenes using existing canonical parity tests. Synthetic bytes and sanitized scene fixtures are allowed; real reference projects and proprietary assets are not.

## Downstream QA

No local downstream application API was available to automate. The generated ZIP must be extracted to a new empty folder, then the manifest file (`<sanitized-name>.ograf.json`) or its declared `main` (`graphic.mjs`) should be loaded by the downstream application. Verify that the shape/text scene renders, the declared public fields are editable, and the image/font assets resolve from the relative `assets/` paths. Report the extracted tree and renderer logs if import fails. Never overwrite a working reference project.
